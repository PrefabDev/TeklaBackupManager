# Security policy / Sécurité

0.1.0-alpha.2 is experimental. There is no stable or certified production release and no support SLA. Maintain independent backups, trusted dedicated folders, least-privilege permissions and tested restoration procedures.

Use GitHub private vulnerability reporting (Security → Report a vulnerability) when available. Do not post secrets, real models, settings, manifests, source registries or raw logs in a public issue. If private reporting is unavailable, request a private contact channel from the maintainer before sending sensitive details.

Provide the version, impact and a fictitious reproducible example. If a real credential is exposed, revoke/replace it and then remove it from files and history; deleting it alone is insufficient.

Version expérimentale, sans garantie de restauration ni délai de correction. Ne jamais publier de données réelles dans une issue. Utiliser le signalement privé GitHub lorsqu’il est disponible ; sinon demander un canal privé au mainteneur avant tout détail sensible.
